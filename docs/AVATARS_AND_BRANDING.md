# Avatars and branding

Profiles have a free avatar picker with preview and save. Migration `20261008130000_avatar_catalog` installs twelve original local SVG avatars and adds `User.avatarId`. The selection is stored in PostgreSQL and returned in authenticated user/profile responses, friend entries, class rosters, and weekly/class/friends ranking entries. A shared avatar component and the header's existing image support display the chosen image; accounts without a choice retain initials. Avatar selection changes no XP, score or level.

`GET /api/v1/avatars` returns active catalog entries. `PATCH /api/v1/users/me/profile` accepts optional `name` and/or `avatarId`; at least one is required. Only the authenticated account is updated. UUID validation, active-catalog lookup, and the existing per-user transaction prevent self-assigned roles, XP, arbitrary image URLs or another user's selection. Stored selections survive fresh sessions and another browser/device.

Administrators use **Avatarlar katalogi** (`/admin/avatars`) to preview, create, rename, reorder and hide entries, choosing from reviewed local images. The admin API is `GET/POST /api/v1/admin/avatars`, and `PATCH /api/v1/admin/avatars/:id`. Hiding an entry removes it from new choices; existing owners retain its image. New reviewed image packs require adding local assets under `apps/web/public/avatars` and their allowed paths to `apps/api/src/profile/avatar-catalog.json`. No arbitrary remote image or upload is accepted by this catalog.

All product branding is configured in `apps/web/src/lib/brand.ts`: name, wordmark/suffix, slogan, description, primary/semantic colors, light/dark logo paths, dimensions, optional wordmark, favicon path and type. Logo and favicon assets live under `apps/web/public/brand`. The Vite HTML transform applies the same values before JavaScript loads; startup sets browser metadata and CSS tokens from that configuration. Login/register, shell/menu, profile membership text, footer and admin overview use these values.

The configured identity is **Bilify**, using the exact logo supplied on 8 October 2026. `bilify-original.png` preserves the input file. `bilify.svg` and `bilify-mark.svg` embed its unchanged pixels in wordmark/symbol viewports, removing presentation margins without redrawing the logo. Both light and dark contexts use the supplied logo; dark contexts give it a white surface to keep the navy lettering readable. The palette combines blue/purple primary actions, bright mint/teal decorative accents, and a darker teal for text. Login, navigation, dashboard cards, lesson paths, progress and user-menu accents use the same tokens.

To replace branding later, edit the brand object and assets. Icon logos use `showWordmark: true`; a full wordmark logo can set it to false and adjust width/height. Set the favicon type to match its file. Internal storage/auth identifiers remain stable to preserve saved drafts and sessions. Badge/unlock avatars belong to a later phase; the twelve starter choices are free.

Verification covers catalog DTOs and role restrictions, unknown/hidden avatar rejection, profile-only avatar changes, persisted selection in a second browser context, friend/class/ranking rendering, mobile picker layout, catalog editing/visibility and brand metadata.
